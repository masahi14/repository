# 訪問対象患者の抽出(毎月の訪問計画用)

## 目的と呼び出し方

訪問患者管理Excelの「患者一覧」を元に、基準日時点の次の2つの候補者一覧を作る。

- **衛生士のみで訪問できる患者** → 「歯科衛生士治療」シート
- **ドクター訪問対象患者** → 「ドクター治療」シート

結果は **担当者が訪問患者と日程を決めるための候補者一覧**。訪問日程・訪問回数・優先順位・点数は一切付けない。

呼び出し例: 「添付した訪問患者管理Excelから、2026年11月1日を基準に訪問対象患者を抽出してください。」

## 毎回必要な入力(スキルに固定しない)

1. **対象のExcel**(毎回ユーザーが指定・添付)
2. **抽出基準日**(毎回ユーザーが指定)

**基準日が指示にない場合は、何も実行せず先に質問する。** 日付の例示(「2026年11月1日」など)が文中にあっても、依頼の基準日として明言されていなければ確認する。基準日をこのファイルやスクリプトに書き込まない。

## 出力の考え方(「新しいエクセル」の解釈)

- 元ファイルは**上書きしない**。結果を反映した別ファイルを出力する(拡張子は元と同じ。`.xlsm` ならマクロはそのまま保持)。
- 抽出先は、そのファイル内の**既存の抽出先シート2枚の更新**。**新しいシートは作らない**。
- 抽出は**数式**で行う(抽出先シートの B2 が基準日。ここを変えると一覧が再計算される)。前回の結果が残ったり患者が重複したりしない。
- 出力ファイルは作業用ディレクトリ(スクラッチパッド)に作り、`SendUserFile` で渡す。**患者データを含むExcelをgitにコミット・push しない**。

## 手順

作業ディレクトリのスクリプト: `.claude/skills/visit-target-extract/scripts/`

### 1. 作業前の確認(必ず最初に実行して、結果を読む)

```bash
python .claude/skills/visit-target-extract/scripts/build_extraction.py inspect --src <対象Excel>
```

出力で次を確認する。

| 確認項目 | 見る場所 |
|---|---|
| シート構成 | `sheets` |
| 元データの見出しと列の対応 | `columns`(見出し→列。列番号は決め打ちしない) / `all_headings` |
| 既存の数式と抽出条件 | `existing_filter`(抽出先シートの現行の抽出条件) |
| プルダウン(入力規則) | `validations`(`x14` は拡張形式。openpyxlで保存すると消える) |
| 選択肢の実際の表記 | `master`(介護保険・ドクター/衛生士治療内容・状態・頻度) |
| 患者情報の対応方法 | 患者ID(重複していないか。患者名だけで照合しない) |
| シート間の連動 | `links`(抽出先を参照している他シート/名前定義があるか) |
| 抽出先の手入力の予定・メモ | `manual_cells`(空であること) |

次のどれかに当てはまるときは**処理を進めず**、具体的に質問する(スクリプトは `[STOP]` で止まる)。

- 見出しが見つからない/複数ある、マスタの選択肢の表記が変わっている(「利用中」「未利用」「定期検診」「ドクター診察・治療なし」「終了」が1つだけ見つからない)
- `manual_cells` がある(抽出先に手入力の予定・メモ)。患者単位で保持できるか確認する(`--allow-manual` は確認済みのときだけ)
- `links.others_refer_to_extract_sheets` がある(他シートが抽出先の列位置を参照している)
- 既存の抽出条件と今回の指示が**矛盾**する(下の「既存の抽出条件との関係」)

### 2. 抽出の実行

```bash
python .claude/skills/visit-target-extract/scripts/build_extraction.py build \
  --src <対象Excel> --base-date YYYY-MM-DD --out <出力先>/<名前>_訪問対象抽出_YYYYMMDD.xlsx
```

内部でやること: ZIP内のXMLを**直接**書き換える(`openpyxl` で保存し直さない。理由は後述)→ LibreOfficeで再計算して計算値を埋め込む(保護ビューなど再計算されない環境でも結果が見える)→ 出力。LibreOfficeがなければ計算値なしで出力し、Excelを開いたときに自動計算される。

### 3. 検証(必ず実行)

```bash
python .claude/skills/visit-target-extract/scripts/verify_extraction.py verify \
  --src <対象Excel> --out <出力Excel> --base-date YYYY-MM-DD
python .claude/skills/visit-target-extract/scripts/verify_extraction.py selftest --out <出力Excel>
```

- `verify` … 変更した部品が想定どおりか(他シート・入力規則・書式が不変か)/ 保存済みの値と、数式を再計算した値と、**数式とは別に書いた独立モデル**の結果が全患者で一致するか / 数式エラーがないか / 重複・残存行がないか / 要確認一覧と理由を出力
- `selftest` … 期限当日・翌日、月末(EDATE)、ちょうど3か月経過、空欄・無効日付・基準日より後・IDの重複・状態=終了などの境界値と、ランダムな約750人分を、複数の基準日で独立モデルと照合
- 終了コードが0でなければ、原因を直すまで納品しない。

あわせて「検証チェックリスト」(下記)を満たしていることを報告に書く。

### 4. 納品と報告

`SendUserFile` で出力Excelを渡し、**次の5点だけを簡潔に**報告する。

1. 使用した抽出基準日
2. 衛生士のみの訪問対象患者数(**確定 n 名**。要確認 m 名は別掲)
3. ドクター訪問対象患者数(**確定 n 名**。要確認 m 名は除外せず表示している旨)
4. 要確認の患者と理由(患者名・理由。`verify` の `check_list`)
5. 検証結果と未解決の問題(あれば内容。ExcelそのものでのOpen確認はこの環境ではできないため、LibreOfficeでの確認である旨を正直に書く)

加えて、`verify` の `ended_but_matching`(状態=終了のため外した患者のうち、今回の条件に合致する人)があれば名前を示し、除外のままでよいか確認する。

実際のExcelを見ても判断できない点だけ質問する。それ以外は、この手順で進める。

## 元データと抽出先

| 役割 | シート | 備考 |
|---|---|---|
| 元データ | `患者一覧` | 1行目が見出し。患者ID・状態が空の行は患者として扱わない |
| 衛生士の抽出先 | `歯科衛生士治療` | 列を下表の11項目+要確認欄に組み替える |
| ドクターの抽出先 | `ドクター治療` | 2項目を非表示にし、要確認欄を追加 |
| 選択肢の元 | `マスタ` | 数式はマスタのセルを参照する(表記を数式に直書きしない) |

対象外のシート・プルダウン・既存機能は変更しない。

## 項目の対応(見出しで対応させる)

`患者一覧` の見出しと、同じ意味の見出し(`build_extraction.py` の `HEADING_SYNONYMS`)。

| 内部名 | 患者一覧の見出し(同義) |
|---|---|
| 患者ID | 患者ID |
| 患者名 | 名前 |
| 介護保険 | 介護保険 |
| 入所施設 | 入所施設 |
| 次回目安日 | 次回目安日(患者一覧のこの列をそのまま表示) |
| ドクター最終診療日 | ドクター最終来院日(=ドクター最終診療日) |
| 衛生士最終診療日 | 衛生士最終来院日 |
| ドクター次回予定 | ドクター次回予定 |
| 衛生士次回予定 | 衛生士次回予定 |
| 口腔機能低下症の最終検査日 | 低下症最終検査日 |
| CR / 抜歯 / 義歯 / SRP / その他 | 同名 |
| 状態 | 状態(「終了」の患者は既存の抽出条件どおり対象外) |

患者情報の対応は**患者ID**で行う(抽出先は患者一覧の行番号で引くので、IDの重複がなければ名前の同姓同名で取り違えない)。IDが重複する患者は要確認にする。

### 衛生士のみ(歯科衛生士治療)の表示項目と順番

1.患者ID 2.患者名 3.介護保険 4.入所施設 5.次回目安日 6.ドクター最終診療日 7.衛生士最終診療日 8.衛生士次回予定 9.SRP 10.口腔機能低下症の最終検査日 11.その他 + 12.要確認(確認が必要な理由)

- SRPは**元データの記録をそのまま表示**する(「n/m」の意味を推測して換算しない)。
- 表示しない: 生活保護・資格確認書・ドクターの前回治療内容・ドクター次回予定・衛生士の前回治療内容・状態・備考・CR/抜歯/義歯。元データからは消さない。
- 日付は `yyyy/mm/dd` で統一。無効な日付も**補正せずそのまま**表示する。
- 1行目に注記「基準日時点の候補者です。訪問日決定時に、ドクター最終診療日からの期限内か再確認してください。」を表示する。

### ドクター(ドクター治療)の表示項目

現行の列と順番を引き継ぐ。**ドクター最終来院日**と**ドクター治療内容**の2列は、列を削除せず**非表示**にする(他の数式・参照を壊さないため)。残す: 患者ID・名前・入所施設・ドクター次回目安日・ドクター次回予定内容・CR・抜歯・義歯・低下症最終検査日・その他。末尾に要確認欄を追加。

## 患者の抽出条件

基準日を B とする。「ドクター最終診療日」は患者一覧の「ドクター最終来院日」(来院履歴から自動取得される列。「ドクター診察・治療なし」の来院は含まない)。

### 衛生士のみで訪問できる患者

次のいずれかに該当する患者。期限は**ドクター最終診療日から暦の月単位**(EDATE)で数え、**期限当日を含む**(B ≦ EDATE(ドクター最終診療日, k))。

| 区分 | 条件 | k |
|---|---|---|
| ① | 介護保険が「利用中」 | 3か月 |
| ② | 介護保険が「未利用」で、衛生士次回予定が「定期検診」 | 2か月 |
| ③ | 介護保険が「未利用」で、衛生士次回予定が「定期検診」以外 | 1か月 |

- 「利用中」「未利用」「定期検診」は**マスタの実際の選択肢**で判定する(前後の空白は無視)。
- 「定期検診以外」と扱うのは、マスタの衛生士治療内容の選択肢にある**定期検診以外の値**のみ。選択肢にない表記(例「定期健診」)は同じ意味か判断できないので分類しない(→要確認の対象)。
- **衛生士次回予定が空欄を「定期検診以外」と自動で扱わない。**

### ドクター訪問対象患者

「ドクター治療」シートの現行の抽出対象(状態が「終了」でない患者)から、**①かつ②**の患者だけを除外する。

- ① ドクター次回予定が「ドクター診察・治療なし」(マスタの実際の選択肢)
- ② 基準日時点で、口腔機能低下症の最終検査日から**3か月が経過していない**(B < EDATE(最終検査日, 3))

| 状況 | 扱い |
|---|---|
| ①だけ該当 / ②だけ該当 | 除外しない |
| 検査日からちょうど3か月(B = EDATE) | 3か月経過済み → 除外しない |
| ドクター次回予定が空欄 | 「治療なし」とみなさない |
| 検査日が空欄・無効 | 「3か月未満」とみなさない |

この3か月は今回の抽出条件であり、検査周期や算定可否を判断する機能は付けない。

## 日付の計算

- 「1か月・2か月・3か月」は30/60/90日ではなく**暦の月単位**(EDATE相当。同じ日がない月は月末。例: 8/31の3か月後は11/30)。
- 「以内」は期限当日を含む。「3か月が経過していない」は、3か月後の日より基準日が前(ちょうど3か月の日は含まない)。
  - ドクター最終診療日 2026/08/01・3か月以内: 2026/11/01は対象、11/02は対象外。
  - 最終検査日 2026/08/01: 2026/11/01時点でちょうど3か月経過(除外条件の②は不成立)。
- **基準日より後の診療日・検査日**は通常の判定に使わず「要確認」にする(対象: 各シートで使う・表示するドクター最終診療日 / 衛生士最終診療日 / 口腔機能低下症の最終検査日)。
- **無効な日付**: 文字列(例「2026/0714」)、日付と認識できない値、2000/1/1より前(例 1900/01/02)または2100/12/31より後。

## 空欄・不明・入力矛盾の扱い(要確認)

勝手に補完・修正・除外しない。**判定に必要な項目が欠けていて結果が割れる場合**、患者を「要確認」として表示する(抽出先シートの右端の「要確認」欄に理由を表示。新シートは作らない)。

方式: 不明な項目が取り得る値をすべて試し、**結果が1通りなら確定**、**割れたら要確認**。

- 別の項目の空欄が抽出判定に影響しない場合は、その空欄だけを理由に患者を除外しない(結果が変わらないなら要確認にもしない)。
- 要確認の理由:

| 理由 | シート |
|---|---|
| 介護保険の利用状況が空欄・不明で、期限が決まらない | 衛生士 |
| 判定に必要なドクター最終診療日が空欄または無効 | 衛生士 |
| 衛生士次回予定が空欄/定期検診と同じ意味か不明で、1か月か2か月か決まらない | 衛生士 |
| ドクター次回予定が空欄/不明表記で、除外条件①を判断できない | ドクター |
| 最終検査日が空欄・無効で、除外条件②を判断できない | ドクター |
| ドクター次回予定が「ドクター診察・治療なし」なのに、CR・抜歯・義歯に進捗の記録がある | ドクター |
| 基準日より後の診療日・検査日がある | 両方 |
| 患者IDが重複しており、患者情報の対応を特定できない | 両方 |

- 一覧の並び: **確定の患者 → 要確認の患者**の順(各グループ内は患者一覧の並び順)。要確認の患者は確定の人数に含めない。
- ドクター側の要確認は「除外せずに表示している」患者である(確定できないものを勝手に除外しないため)。

### CR・抜歯・義歯の進捗の扱い(未確定事項)

元ファイルには、CR/抜歯/義歯/SRPの「n/m」の記録方法の説明が**ない**(例: `0/2`)。意味(実施回数/必要回数なのか、次回の回数/必要回数なのか)を推測しない。そのため現状は「**何らかの記録があること**」を「未完了の可能性あり」として要確認にしている(完了/未完了を判断していない)。ユーザーが記録方法を回答したら、`build_extraction.py` の `dr_helpers` の `V`(記録あり判定)をその規則に置き換え、`verify_extraction.py` のモデル(`model_dr` の `prog`)も同じ規則に合わせ、この節を更新する。

### 既存の抽出条件との関係

現行の抽出先は「患者IDがあり、状態が『終了』でない患者」を全員並べる作りで、これを今回の抽出の土台にしている。**状態=終了の患者は引き続き対象外**(既存条件)。今回の条件を満たす終了患者がいる場合は報告で名前を示して確認する。過去の条件が残っていることだけを理由に、それ以外の患者を除外しない(例: 次回目安日が先であることを理由に除外しない)。

## 既存シートの更新方法(壊さないために)

- **`openpyxl` でこのファイルを読み込んで保存しない。** プルダウンと一部の色分けは拡張形式(x14)で保存されており、openpyxlは警告だけ出して黙って消す。このスキルはZIP内のXMLを直接書き換え、他の部品はバイト単位で不変。
- 変更するのは、抽出先2シートのXML・`styles.xml`(書式を末尾に追加するだけ)・`workbook.xml`(再計算フラグ、フィルターの名前定義)・`calcChain.xml`(数式を変えるため削除。Excelが自動再作成)。
- 抽出先シートの全体を作り直すため、再実行しても重複・残存が出ない(処理済みファイルに別の基準日で再実行すると、元ファイルから作った場合とバイト単位で同じになる)。
- 補助列: P〜AD列は非表示(P=抽出キー、Q=患者一覧の行番号、R〜AD=判定用。1行目に見出しあり)。`ドクター治療`/`歯科衛生士治療` の既存のP・Q列と同じ役割。
- 基準日の入力: `歯科衛生士治療`!B2(入力セルは保護の対象外)。`ドクター治療`!B2 はそれを参照する。
- 見た目: 1〜3行目と見出しを固定、オートフィルター(見出し行の▼)、日付は yyyy/mm/dd、色だけに頼らず文字で判断できる。既存の色分けは、列が動いたものだけ付け替えて維持。
- 判定の詳細(補助列の意味・数式の仕様・テスト一覧): `references/spec.md`

## 検証チェックリスト(毎回)

- [ ] 介護保険利用中の患者に3か月の条件が適用されている
- [ ] 介護保険未利用の定期検診の患者に2か月の条件が適用されている
- [ ] 介護保険未利用の定期検診以外の患者に1か月の条件が適用されている
- [ ] 期限当日は対象、期限を超えた日は対象外(selftestの名前付きシナリオ)
- [ ] ドクターの除外が「①かつ②」(①だけ・②だけは除外しない)
- [ ] 検査からちょうど3か月経過した患者を、3か月未満として除外していない
- [ ] 空欄・無効な日付・入力矛盾が誤判定されていない(要確認の理由を目視確認)
- [ ] 患者情報のずれ・重複・前回結果の残存がない
- [ ] 既存の数式・入力規則・シート間の連動が壊れていない(`verify` の `integrity`)
- [ ] 数式エラー・XML不正がない(`verify`)。Excelでの修復警告の有無は、この環境ではExcel自体で確認できないため、LibreOfficeでの読み込みとXML整合の確認にとどまることを報告する

## この環境での注意

- 計算値はLibreOfficeで再計算して埋め込む。患者一覧側の既存の計算値は、元ファイルをExcelで保存したときの値をそのまま使う(元ファイルが数式の計算値なしで保存されている場合は、先にLibreOfficeで再計算してよいか確認する)。
- `selftest` はLibreOfficeを十数回起動するため、1〜2分かかる。
