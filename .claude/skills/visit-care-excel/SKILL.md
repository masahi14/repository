# 訪問診療患者管理Excel運用

## このスキルについて

このExcel(通称「訪問診療患者一覧.xlsx」)は、単発の依頼ではなく、長い会話の中で少しずつ
仕様を積み上げてきた1つのシステムです。新しいセッションでこの続きを頼まれたとき、毎回ファイルを
開いて構造をゼロから調べ直すのは非効率で、しかも調べ間違えるとユーザーの実運用データを壊しかねません。
このスキルは「今のファイルが何でできているか」を先に渡しておくためのものです。

似た名前・似た構成の別ファイル(例えば同じクリニックの別バージョン)を渡された場合でも、まず
このスキルに書かれた列構成・シート名を仮説として使い、実際のファイルを読んで差分がないか確認して
から作業してください。差分があれば、それは持ち主が運用の中で更新した可能性が高いので、上書きせず
尊重してください。

**シートに「ドクター治療」「歯科衛生士治療」がある別系統のファイル**(「治療追加⑧衛生士治療内容①」など)
を渡されたら、先に `references/variant-chiryo-tsuika.md` を読むこと。構成・壊れやすい箇所・
過去のエラー原因(来院日の文字列入力で全シート #VALUE!)がまとめてある。

## ファイル構成(シート)

| シート名 | 役割 |
|---|---|
| 使い方 | 操作説明。青系太字の見出し(Arial 12pt, 色FF1F4E78)+本文(Arial 10pt) |
| 患者一覧 | メインデータ。A〜AC列、300行分の枠。列の詳細は `references/schema.md` |
| 担当別 | ドクター/衛生士別に次回目安日を出すビュー(患者一覧と自動連動、直接編集しない) |
| Dr訪問候補 | ドクター対応が必要な患者を優先度順に自動抽出するビュー |
| DH訪問候補 | 衛生士対応が必要な患者を優先度順に自動抽出するビュー |
| 施設別 | 入所施設ごとに自動で並び替えるビュー |
| 来院履歴 | 来院記録の入力シート。ここに1行追加すると患者一覧の最終来院日・治療内容が自動更新される |
| マスタ | 各種プルダウンの選択肢と、優先度スコアの重み・ポイント設定 |

列の細かい意味、優先度スコアの計算式、マスタの配置は `references/schema.md` を参照してください
(毎回SKILL.mdに読み込むには長すぎるので、実際に列やスコアを触るときだけ読めば十分です)。

## 最重要: データ検証(プルダウン)を絶対に壊さないこと

**背景**: このファイルのプルダウンは、Excelの拡張形式(`x14:dataValidation`)で保存されています。
これは openpyxl が読み書きに対応していない形式で、`load_workbook` → `save` を行うだけで、警告
(`Data Validation extension is not supported and will be removed`)だけ出して**黙って消えます**。
このスキルを作るきっかけになったのが、実際にこれで来院履歴・患者一覧の主要なプルダウンが軒並み
効かなくなった事故でした。1回の編集では気づきにくく、何度も編集を重ねるうちに全滅する、という
性質のバグなので、「今回は関係ない列しか触っていないから大丈夫」という判断は禁物です。
**openpyxlでこのファイルを保存する処理を行ったら、必ず毎回、後述のスクリプトで標準形式の
データ検証を再設定してから納品してください。**

やること: 保存後のファイルに対して `scripts/restore_data_validations.py` を実行する。

```bash
python scripts/restore_data_validations.py <保存したxlsxのパス>
```

このスクリプトは、患者一覧・来院履歴に必要なプルダウン(介護保険・生活保護・資格確認書・入所施設・
訪問頻度・状態・患者ID・ドクター治療内容・衛生士治療内容)を、標準(非x14)形式で全て書き戻します。
中身は決め打ちの範囲リストなので、新しい列に新しいプルダウンを追加した場合は、このスクリプトにも
追記してください(スクリプト内にコメントで一覧があります)。

## 作業フロー

1. ユーザーがアップロードしたファイルは、そのセッションのscratchpadディレクトリにコピーしてから
   作業する(アップロード元や以前の成果物を直接上書きしない)。
2. openpyxl で編集する。既存のスタイル規約に合わせること:
   - フォントはArial。本文10pt、見出しは太字。
   - ヘッダー色: **青(FF2F5C8A)= 手入力列**、**緑(FF1F7A6C)= 数式・自動計算列**。この色分けは
     ユーザーとスタッフが「触ってよいセル」を見分ける唯一の手がかりなので、新しい列を足すときも
     必ずこのルールに従うこと。
   - 罫線は薄いグレー(D9D9D9)のthin、数式セルは`Protection(locked=True)`、入力セルは`locked=False`
     (シート保護が有効なので、ロック設定を間違えると入力できなくなる)。
3. 保存後、`scripts/restore_data_validations.py` を実行する(上のセクション参照。省略しないこと)。
4. LibreOffice (`soffice --headless --calc --convert-to xlsx --outdir <tmp> <file>`) で再計算した
   コピーを別途作り、数式が正しく計算されているか(エラー値 `#REF!` や「要確認」が出ていないか、
   Dr/DH訪問候補などの抽出件数が妥当か)を確認する。**このLibreOffice変換版はあくまで検証用**で、
   ユーザーに渡すのは手順3までで作った(再計算前の)openpyxl生成ファイルの方。LibreOfficeでの
   変換は書式やx14拡張機能をさらに壊すリスクがあるため、納品物には使わない。
5. 検証が通ったら `SendUserFile` でユーザーに渡す。作業用の一時ファイル(LibreOffice変換版、検証用
   サンプルデータを入れたコピーなど)は送らない・残さない。

## このクリニック特有の情報(参考)

- 入所施設は現在「ハートワン潮来」「養護老人ホーム潮来」の2つ。
- ドクター側の治療内容・必要回数の仕組みはまだ検討中(2026年時点)。決まったら、衛生士のSRP回数
  表示(`references/schema.md` のAC列)と同じ考え方(必要回数入力 → 実施回数入力 → 自動で
  「n/m」表示)で追加する想定。
- 優先度スコアのポイント配点(マスタシート)は暫定値。クリニックの運用判断で随時変わりうるので、
  数式のロジックさえ壊さなければ、数値自体を「正しく直す」必要はない。
