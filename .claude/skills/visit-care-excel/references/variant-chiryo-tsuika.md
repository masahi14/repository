# 別バージョン「治療追加⑧衛生士治療内容①」系ファイルの注意点

SKILL.md に書いた構成とは別系統のファイル(2026年10月時点)。Dr訪問候補/DH訪問候補シートはなく、
代わりに「ドクター治療」「歯科衛生士治療」シートがある。

## シート構成
使い方 / 患者一覧(A〜V列) / 担当別 / 施設別 / 来院履歴(テーブル VisitHistory) /
ドクター治療 / 歯科衛生士治療 / マスタ

- 患者一覧 Q〜T列 = CR・抜歯・義歯・SRP の回数を "2/6" のような**文字列**で手入力(列書式は文字列 @)。
  U = 低下症最終検査日、V = その他。
- 患者一覧 I〜N, P列は来院履歴から自動取得。担当別・施設別・ドクター治療・歯科衛生士治療は
  患者一覧の行番号(各シートの Q列)経由で INDEX 参照している。
- **scripts/restore_data_validations.py はこのファイルには使わないこと**(範囲が違う)。
  プルダウン・条件付き書式は x14 拡張に入っているので、openpyxl で保存せず XML を直接編集する。

## 2026/10 に起きた全シート #VALUE! の原因
来院履歴A列(来院日)に「2026/1027」(スラッシュ抜け)が入力され、日付ではなく文字列になった。
旧数式 `SUMPRODUCT(MAX((条件)*来院履歴!$A$2:$A$200))` は配列中の文字列1つで #VALUE! になり、
全患者の I〜P列 → 担当別・施設別・ドクター治療・歯科衛生士治療 まで連鎖した。

修正版で入れた対策(同系統ファイルを直すときの参考):
- I〜N, P列を `_xlfn.AGGREGATE(14,6, 値/(条件), 1)` 方式に変更。文字列や空欄の日付はエラー扱いで
  無視されるので、1件の入力ミスで全体が壊れない。`_xlfn.` を付けないと LibreOffice/Excel で #NAME?。
- 同じ患者・同じ日付の行が複数あると、旧数式は行番号を**合計**して別の行を参照していた。
  AGGREGATE で「最後に入力された行」を取るように修正。
- 参照範囲を来院履歴 1〜3001行に拡大(旧: 2〜200行で、約3か月で溢れる)。1行目始まりなので
  先頭行への挿入でも範囲から外れない。テーブル範囲・C/D列の数式・プルダウン範囲も3001行まで拡大。
- 来院履歴A列に日付の入力規則(2020/1/1〜2099/12/31)、患者IDプルダウンにエラー表示を追加。
- 来院日・患者IDの入力ミス行を赤く表示する条件付き書式を追加。
- INDEX が空欄を 0 と返す問題(患者一覧K列、施設別)を `&""` / `IF(INDEX()="","",INDEX())` で解消。

## 検証環境メモ
- この環境の LibreOffice は calc が入っていないことがある(`source file could not be loaded`)。
  `apt-get install -y libreoffice-calc` で解決。
- 旧数式のままのファイルは LibreOffice の再計算が5分以上かかる。AGGREGATE 版は数秒。
- XML を直接編集したら calcChain.xml を削除し、`<calcPr fullCalcOnLoad="1"/>` を付けておく。
