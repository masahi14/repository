# 患者一覧シート 列構成の詳細

(FIRST_DATA_ROW=2, LAST_DATA_ROW=301。300人分の枠を確保している)

## 手入力列(青ヘッダー FF2F5C8A)
| 列 | 見出し | 内容 |
|---|---|---|
| A | 患者ID | 一意な数値ID |
| B | 名前 | |
| C | 介護保険 | プルダウン: マスタ!$L$2:$L$3(利用中/未利用) |
| D | 生活保護 | プルダウン: マスタ!$N$2:$N$3(該当/非該当) |
| E | 資格確認書 | プルダウン: マスタ!$P$2:$P$3(あり/なし) |
| F | 入所施設 | プルダウン: マスタ!$A$2:$A$30 |
| G | 訪問頻度 | プルダウン: マスタ!$C$2:$C$7(月1回/隔週/週1/2か月1回/3か月1回/不定期) |
| O | 状態 | プルダウン: マスタ!$T$2:$T$2(選択肢は「終了」のみ。終了した患者はここを選ぶ。空欄=通院中) |
| Q | ドクター必要回数 | 数値。今のコース全体で必要な回数(任意入力) |
| R | ドクター実施回数 | 数値。これまで実施した回数(任意入力) |
| S | 衛生士必要回数 | 数値。SRPなど複数回処置の必要回数(任意入力) |
| T | 衛生士実施回数 | 数値。これまで実施した回数(任意入力) |

## 数式・自動計算列(緑ヘッダー FF1F7A6C、Protection locked=True)
| 列 | 見出し | 計算内容 |
|---|---|---|
| H | 次回目安日 | `MAX(I,L)` + マスタの頻度別日数。G="不定期"またはI・L共に空なら"未定" |
| I | ドクター最終来院日 | 来院履歴からその患者の最新のドクター対応日を自動取得 |
| J | ドクター治療内容 | 直近のドクター対応で実施した内容(来院履歴由来) |
| K | ドクター次回予定 | 次回ドクターが行う予定の内容。"ドクター診察・治療なし"は「対応不要」を意味する特別値 |
| L | 衛生士最終来院日 | 最新の衛生士対応日 |
| M | 衛生士治療内容 | 直近の衛生士対応内容 |
| N | 衛生士次回予定 | 次回衛生士が行う予定の内容 |
| P | 備考 | 来院履歴の最新メモを自動要約 |
| U | ドクター残り回数 | `MAX(Q-R, 0)`。Qが空なら空欄 |
| V | 衛生士残り回数 | `MAX(S-T, 0)`。Sが空なら空欄 |
| W | ドクター次回目安日 | `I + マスタの頻度別日数`(Hとは別に、ドクター単独の目安日) |
| X | 衛生士次回目安日 | `L + マスタの頻度別日数`(衛生士単独の目安日) |
| Y | ドクター優先度スコア | 下記「優先度スコアの計算」参照。対象外(K空欄・"ドクター診察・治療なし"・状態=終了・Wが日付でない)なら空欄 |
| Z | 衛生士優先度スコア | 同上。対象はN空欄でないこと、状態≠終了、Xが日付であること |
| AA | (Dr並び替えキー) | `-Y + ROW()/100000`。Dr訪問候補シートのSMALL関数がこれを昇順に拾うことで、スコア降順を実現している |
| AB | (DH並び替えキー) | 同上、Z・DH訪問候補用 |
| AC | 衛生士回数表示 | `S,T`から `"n/m"` または `"完了"` を計算。次のセクション参照 |

## 優先度スコアの計算

```
スコア = (TODAY() - 次回目安日)              … 期日超過日数。未来ならマイナス
        + 残り回数 × マスタ!$B$17            … 重み。初期値5(1回あたり5日分)
        + 治療内容ごとの優先度ポイント          … マスタの配点表から VLOOKUP
```

- ドクター用ポイント表: `マスタ!$A$19:$B$26`(K列=次回予定の値をキーに検索)
- 衛生士用ポイント表: `マスタ!$A$29:$B$35`(N列=次回予定の値をキーに検索)
- Dr訪問候補・DH訪問候補シートでは、このスコアそのものではなく「あと5日」「3日超過」という
  文字列表示に変換して見せている(スタッフ全員にとって分かりやすくするため)。色分けは
  赤=14日以内(次回目安日からの残り日数<=14)/オレンジ=15〜30日/グレー=31日以降。

## 衛生士回数表示(AC列)の計算

SRPのように複数回にわたる処置の「今何回目か」を "1/4"→"2/4"→…→"完了" のように表示する。

```
done = IF(T="", 0, T)
AC = IF(S="", "", IF(done >= S, "完了", (done+1) & "/" & S))
```

Sが空欄(必要回数が未入力)ならACも空欄。実施回数が必要回数に達したら"完了"と表示される。
ドクター側にも同じ仕組みを追加する予定があるが、2026年時点ではまだクリニック側で治療内容が
未確定のため、Q・R列を使った同様の表示列(仮に"AD列"などになる)はまだ実装していない。
追加する際は、このACの計算式をそのままQ・R列版として複製すればよい。

## Dr訪問候補 / DH訪問候補シートの構造

見た目上の列(A〜J): 順位, 患者ID, 名前, 入所施設, 目安日までの日数, 残り回数(DH側はAC列の
"n/m"表示に差し替え済み), 次回目安日, 直近の治療内容, 次回予定内容, 備考。

裏方の計算列(M,N,O、狭い列幅で目立たなくしている):
- M: `SMALL(患者一覧!$AA:$AA または $AB:$AB, k)` でk番目に小さい並び替えキーを取得
- N: `MATCH(M, 同じ範囲, 0) + 1` で、それが患者一覧の何行目かを求める
- O: 次回目安日からの残り日数(数値)。条件付き書式の判定にだけ使う裏方セル

この2シートは共に300行分の枠を持ち、対象外の患者は行ごと空欄になる(IF文でキーが空なら
その行全体が空欄になる設計)。
