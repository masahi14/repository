## プロジェクトの目的

歯科医院(院長がユーザー)の電子カルテ入力ソフト(Windowsデスクトップアプリ、レセコン一体型)で、スタッフが毎回同じ組み合わせで手作業により選択・入力している処置コード・指導文言を、画面隅の常時表示ボタンパネルからワンクリックで自動入力できるようにするツールを開発している。院内20台のPC(共有フォルダで接続、IT担当は「桐生さん」、最終決定権は院長)に展開する。

## 最重要の安全制約(絶対に忘れてはいけない)

検討の過程で、血圧・SpO2・脈拍などの**実測値**や、実地指導などの**実施時刻**をランダム生成してカルテに自動入力したいという要望が出たが、これは実際に測定・実施していない数値をカルテに記載することになり、**診療録の虚偽記載・診療報酬の不正請求リスク**に直結するため明確に却下し、対象から除外した(血圧セットはスコープ外)。

**本ツールが自動入力してよいのは、臨床的な事実に基づいてスタッフが選ぶ処置コード・定型文言・メニュー選択のみ。測定値・時刻など事実を表す数値は絶対に自動生成しない。** これは今後も新しい要望が来るたびに必ず確認すること。コード上も `src/lib/InputEngine.ahk` の `_HandleLeaveBlankManualEntry()` や `config/sets.schema.json` のフィールド制限で多層的に担保している(詳細は `docs/architecture.md`)。方法2(処置選択表のメニュー選択)も、あらかじめ決められた固定のキー操作を再生するだけで、画面を読み取って動的に判断したり数値を入力したりすることは一切ない。

## カルテソフトの入力方式に関する発見と対応状況(実装済み・データ反映待ち)

カルテソフトには**2種類の入力方法**がある。

- **方法1(コード入力)**: 画面上の入力欄にフォーカスを合わせた状態で5桁の数字コードを入力しEnter。`config/sets.json` では項目に `code` を持たせる。
- **方法2(処置選択表からのメニュー選択)**: `Shift+F1` → `F2` で「処置選択表」という画面を開き、そこから数字キーまたは上下矢印キーで階層メニューをたどり、Enterで確定する。マウスクリックは不要で、キーボードだけで完結する(メーカー確認済み)。`config/sets.json` では項目に `menu_path`(基準状態からEnter確定までの完結したキー列。例: `["+{F1}", "{F2}", "{Down}", "{Down}", "{Enter}"]`)を持たせる。

`fullmouth_xray_comment` セットの18項目のうち一部と、`denture` セットの指導文言17項目+「咬合機能の回復について説明」は、5桁コードが存在しないことがメーカー確認済みで判明しており、方法2でしか入力できない。

### 今回のセッションで完了したこと

1. **スキーマ拡張**: `config/sets.schema.json` の `item` 定義を `code_item`(方法1)と `menu_item`(方法2、`menu_path`)の `oneOf` に変更し、`menu_key`(AutoHotkey v2のSend形式キー1つ分の文字列)の定義を追加した。
2. **バリデーション拡張**: `src/lib/ConfigLoader.ahk` の `_ValidateItem` を、`code` と `menu_path` のどちらか一方のみを許可するように拡張し、`_ValidateMenuKey` を追加した。
3. **実装拡張**: `src/lib/InputEngine.ahk` に `SendMenuPath(menuPath, settings)` を追加し、`RunSet` が項目ごとに `code`/`menu_path` を見て方法1・方法2を振り分けるようにした。数値・時刻を送信する関数は引き続き一切実装していない。
4. **設定追加**: `config/settings.json` に、方法2のキー送信間隔用の `timing.after_menu_key_ms` を追加した。
5. **静的チェック更新**: `tests/config-validation/check-forbidden-patterns.ps1` の許可フィールド一覧に `menu_path` を追加し、`menu_path` の中身がキー名文字列以外(数値等)になっていないかも検出するようにした。
6. **ドキュメント更新**: `docs/requirements.md`(方法1/方法2の記述、未確定事項の更新)、`docs/architecture.md`(方法2のアーキテクチャ・実装方針)、`docs/admin-guide.md`(`menu_path` の説明。桐生さん・院長が直接書く必要はなく、スクリーンショットを送ってもらえばClaudeが記入する旨を明記)を更新した。
7. コミット・プッシュ済み(このブランチ・PR #6へ)。

**注意**: `config/sets.json` 自体の中身(`fullmouth_xray_comment` と `denture` の該当項目)はまだ更新していない。実装(スキーマ・エンジン)は方法2に対応したが、実際のキー操作列(`menu_path` の中身)はスクリーンショットが届いてから算出・反映する。現状はまだ「TODO: 実コードに差し替え」という仮の5桁コードのプレースホルダーのままになっている。
