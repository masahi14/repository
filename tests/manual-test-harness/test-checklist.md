# 手動動作確認チェックリスト

実際の電子カルテソフトはこの開発環境から操作できないため、`dummy-karte.ahk`(この配下)をカルテソフトの代役として使い、以下を確認する。実機での最終確認は桐生さんとのパイロット運用時に別途行う。

## 準備

1. `config/settings.json` の `test_mode` が `true` になっていることを確認する(初回は必ずON)。
2. `tests/manual-test-harness/dummy-karte.ahk` を起動する。
3. `src/main.ahk` を起動する(パネルが画面の隅に表示される)。

## テストモード(test_mode: true)での確認

- [ ] パネルの各ボタンを1回ずつ押し、`%LOCALAPPDATA%\DentalKartePanel\logs\<日付>.log` に `[TEST MODE - not sent]` としてセットIDとコード列が記録されることを確認する。
- [ ] `spt` (SPT)を複数回(10回程度)実行し、ログ上で選ばれるコードが毎回 `pick_count` の件数であり、同一実行内で重複がなく、実行ごとに組み合わせが変わることを確認する。
- [ ] 実キー送信が行われていないこと(ダミーカルテのテキストボックスに何も入力されないこと)を確認する。

## 実送信モード(test_mode: false)での確認

`config/sets.json` 内の `"TODO: 実コードに差し替え"` を実コードに置き換えたうえで行うこと。ダミーコードのままでも動作確認自体は可能。

- [ ] ダミーカルテのテキストボックスをクリックしてフォーカスを合わせる。
- [ ] 固定フルセット(`hygiene_instruction` 等)のボタンを押し、`items` に定義した通りの順番・個数のコードが入力されることを確認する。
- [ ] `hygiene_instruction` の最後(43771、`leave_blank_manual_entry`)を送信した際、コード+Enterの後に**何も追加入力されない**ことを確認する(空欄のまま残る想定を担保)。
- [ ] `spt`(ランダム抽出セット)を複数回実行し、毎回 `pick_count` 件のコードが入力され、実行間で組み合わせが変わることを確認する。
- [ ] ボタンを押している間、他の6つのボタンが無効化(クリックできない状態)になり、完了後に再び有効化されることを確認する。
- [ ] ボタンをクリックしても、ダミーカルテのウィンドウがアクティブなまま(フォーカスが奪われない)であることを確認する。
- [ ] 送信中にダミーカルテ以外のウィンドウ(例: メモ帳)を一時的にアクティブにしてからパネルのボタンを押した場合、`lastActiveHwnd` の追跡により正しくダミーカルテにフォーカスが戻ってから送信されることを確認する。

## パネルのUI確認

- [ ] パネルの背景(ボタン以外の部分)をドラッグして移動できることを確認する。
- [ ] `main.ahk` を再起動し、直前の位置が復元されることを確認する。
- [ ] トレイアイコンの右クリックメニューから「設定を再読み込み」「設定フォルダを開く」「ログフォルダを開く」「終了」がそれぞれ動作することを確認する。

## 異常系の確認

- [ ] `config/sets.json` の中身をわざと壊す(例: 閉じ括弧を1つ消す)→ 再読み込み時にエラーメッセージが表示され、直前の正常な設定に自動的に戻ることを確認する。
- [ ] `sets.json` に許可されていないフィールド(例: `"value": 120`)を追加する → 起動時・再読み込み時にバリデーションエラーとして拒否されることを確認する(数値自動生成の混入を防ぐ安全弁の確認)。
